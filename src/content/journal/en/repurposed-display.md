The project explores using a Motorola Moto X display inside the deck. Its role is distinct from the external television: it can provide a front-panel interface while the video output follows its own path.

That separation opens up an interesting question. How much information belongs on the object itself, and how little can be shown while keeping it useful?

## Design for the opening

The visible area, viewing angle and position behind the front panel will define the interface. Before choosing type sizes or animation, the display needs a physical mock-up in the intended opening.

A small number of high-contrast elements will be easier to read than a scaled-down desktop interface. A channel, a playback state or a single graphic can be enough.

## Give each screen a job

The front-panel display can communicate the deck’s state. The television can carry the programme. Keeping those roles distinct should make the object easier to understand.

The illustration above is a visual study, not a capture from the Android application or a claim about the final hardware.

## Questions to resolve

- How will the display be mounted and serviced?
- What should appear while the playback system starts?
- How should the interface behave when the player stops responding?
- Which information remains useful from across a room?

## Next step

Build a full-size front-panel mock-up and test a simple screen in the actual opening. Record readability, reflections and access before committing to a permanent mounting solution.
